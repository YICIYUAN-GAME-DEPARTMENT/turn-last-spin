# 产品目标、交付范围与成功定义

> **2026-11-18 最新技术方向：P2P**。原文中的“固定公网权威服务器”是已被覆盖的旧推荐；不影响 2～12 人、公网跨网可玩、秘密决策和一致结果等 P0 验收，详见 [架构选项](../02-architecture/03-p2p-architecture-options.md)。

> 状态：评审草案。输入为《TURN · 轮盘博弈：在线多人游戏需求与边界》v0.1。  
> 任何标记「建议」的技术选择不得视为玩法已确认变更。

## 1. 项目定位 [确定]

- 项目名称：TURN: Last Spin；一款 GameJam **在线多人**公开信息、同步秘密决策、轮盘淘汰的派对策略游戏。
- 人数：每局 **2～12 名真人**；默认以 8 人局作为主要体验场景。
- 首发验证目标：Windows PC、Godot 4；当前空工程配置是 Godot 4.7/GL Compatibility，具体补丁号待核对。
- 在线完成标准：**至少两台处于不同网络的设备经实际公网连接，从建房到胜负完成一整局，结果一致**。同机多开、局域网或模拟人机不替代公网验收。
- 三段体验：公开手牌观察 → 预判他人秘密行动 → 一次性揭晓与淘汰。
- 比赛主题、提交时间、成员及职责、服务器提供方、测试设备：目前**未给出**。

## 2. 唯一已确认的规则基线 [确定]

见 [规则全文](../01-gameplay/01-rules.md)，精简版：

1. 存活玩家每轮各新增 1 张 **明牌**，牌面随机取 `1..当前存活人数`，独立抽取，允许重复；旧牌保留、旧数值不变。
2. 本轮轮盘只包含当前存活者，按现有顺序排列；服务端在其中**等概率随机**公布初始指向。
3. 每人只可选择 **不出牌** 或 **打出手牌中的一张，并选择 + 或 -**；确认后锁定，所有行动统一公开。
4. 位移相加后按存活人数循环，最终落点对应玩家**扣 1 点生命**；生命归零才淘汰，正常每轮命中一人。
5. 打出的牌永久弃置，出局者未出牌全部弃置，**不发生手牌继承**；剩 1 人结束。
6. 下轮按剩余玩家相对顺序重新给**轮盘位置编号**，不改变玩家的稳定身份和显示名称。

## 3. P0（必须交付）

| 编号 | 必须完成 | 判定依据 |
| --- | --- | --- |
| P0-01 | P2P 公网可达连接与多客户端 | 非同网两机加入同一房间 |
| P0-02 | 房间码建房、加入、成员、准备、开始 | 2～12 人；错误原因可见 |
| P0-03 | 服务端发牌、随机初始指向、广播明牌 | 客户端状态一致；不能自行发牌 |
| P0-04 | 秘密选择、确认锁定、到期/全员确认统一公开 | 公开前绝不把别人的选择发给其他客户端 |
| P0-05 | 一致且可验证的权威/共识结算、循环位移、弃牌、淘汰、终局 | 裁决者与防作弊模型仍待 P2P 决策，不信任无校验的动作或结果 |
| P0-06 | 超时不出牌、掉线不阻塞、房间隔离 | 有期限、有阶段校验、有清理 |
| P0-07 | 轮盘、方形牌框、玩家身份、倒计时、统计 | 2/8/12 人可操作，公开手牌完整可检查 |
| P0-08 | 可运行 P2P 客户端、联机连接/平台依赖说明、可复现验收 | A01～A11 记录、跨网完整对局证明 |

## 4. P1（核心闭环稳定后择优）

- 美术主题、动画、音效、更多牌面视觉反馈。
- 服务端统一控制的机器人补位；更聪明的人机策略。
- 断线重连、邀请链接、完善的异常恢复。
- GameJam 主题硬性要求可能使某项升为 P0，由队长决定。

## 5. 明确不做（首版）

- 暗牌、出局手牌继承、技能牌、复活、新胜利条件。
- 账户系统、好友、段位、匹配、排行、跨局成长。
- 内置文字/语音聊天、录像与赛事管理。
- 中途旁观加入、服务器中断后的整场恢复、额外平台。
- 普通玩家承担公网开端口/端口映射的复杂配置。

## 6. 源文档勘误与适配

原始 `turn.md` 将「已有本地人机原型」列为现状，并引用 `scripts/game.gd`、`scripts/main.gd`、`scripts/wheel.gd`、`scripts/player_cards.gd`、`scripts/bot.gd`。

**现场检查结果：上述文件不存在。** 项目仅有 Godot 初始化文件。因此：
- 不开展「接手原型、提取已有规则、重构原代码」工作；改为按本组文档**从零实现**。
- 「所有人机共用规则」是未来扩展约束，不是当前已实现能力。
- 以游戏规则先行、网络边界从第一天分离的方式安排实现顺序。
- 原文的 UI 约束（例如「轮盘中央空白、扇区不显示编号、方形牌框」）仍有效。

## 7. Done 定义（产品级）

**可以宣布 P0 完成**仅当：按验收文档验证房间生命周期、牌数恒等式、秘密提交、多人一致性、超时及掉线、12 人布局，以及至少一场真实跨公网完整对局，并有可运行构建及启动说明。

不能因为已经实现「网络连接」或「单机规则」就称作在线功能完成。

## 8. 2026-11-18 已批准的玩法流程默认值

- D-02：采用 Godot 4.7 + GDScript；团队补丁版待统一。
- D-04：房主建房、凭码加入，成员至少 2 人且全员准备后由房主开始；保持 2～12 人范围。
- D-05：每轮 **15 秒**，全部存活玩家确认即可提前公开；截止未确认者自动 PASS。
- D-06：开局前退出移除成员；对局中断线保留席位、已确认行动保留、未确认和后续回合自动 PASS，不立即淘汰。
- D-07：游戏结束后返回原房间并重新准备，不接受比赛中途加入。
- D-08：人机补位是 P1，真人联机是 P0。
- D-03：联机架构、具体传输方式和部署仍待讨论；**权威结算这一 P0 要求不变**。

本节是对原始 v0.1 的流程细化，不是对服务器实现方式的批准。最小 Host-Client Demo 已实施，完整公网验收尚未完成。

## 9. 最新确认：P2P 优先（覆盖原 v0.1 的服务器实现建议）

原始上传 `turn.md` v0.1 §7.1 推荐固定公网专用权威服务器；**用户现已明确要求 P2P**，替代旧部署路线，但没有取消公网不同网络可玩、严格秘密提交、一致结算等产品目标。若选房主型 P2P，房主自己的客户端承担逻辑协调/权威职责；若选 Mesh，还要定义一致性协议。短房间码发现、NAT 穿透、Host 秘密性及掉线后的恢复均未决。详见 [P2P 技术方案](../02-architecture/03-p2p-architecture-options.md) 与 [决策簿](02-open-decisions.md)。

## 10. 生命系统的新需求与最小 Demo 实现

用户于 2026-11-18 提出“初始生命可调整”。本版由 Host 在大厅设置所有玩家相同的初始生命，整数 **1～5**、默认 1；每次轮盘命中扣 1 点，生命为 0 才淘汰。默认 1 生命时与原始一轮一淘汰玩法一致。该新增规则已经在最小 Demo 实现，但原稿中依赖“每轮淘汰”的回合/手牌上界只适用于默认 1 生命。详见 [生命设置规则](../01-gameplay/03-initial-lives.md)。
